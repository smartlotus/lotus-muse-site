# 先让 Muse 自己回答这 6 件事（决定用哪种架构）

思路：Muse 有一台自己的云电脑（VM），里面有代码执行能力。如果那台机器能装/有 node 与 git、
能出网、能长期持有凭据，那最省事的维护方式就不是"给它一个接口让它调"，而是
**"把仓库给它，它自己在里面干活并 push"**。

这件事不能靠猜。把下面整段原文粘给 Muse，让它逐条**实测并回报证据**。
它只被要求读信息与跑无害命令，不允许改你任何东西。

```text
我需要判断你当前的运行环境能不能承担一个长期任务：把一个 GitHub 仓库克隆到你自己的工作环境里，
在里面运行 Node 脚本修改内容，再提交并推送，让 Cloudflare Pages 自动部署。
请不要凭印象回答，逐条实测后把原始输出贴回来；测不出来就明确说测不出来。不要执行任何写操作，
不要碰我的仓库，也不要向我索要任何密钥。

1. 你在哪个环境里执行命令？给出你实际调用的工具名与这条命令的原始输出：
   uname -a; pwd; whoami; echo $HOME
2. Node 与包管理：node --version; npm --version。若没有 node，说明能否安装（写清楚你打算用哪条命令），
   但不许现在安装。
3. Git：git --version; git config --global user.name; git config --global user.email。
4. 出网能力：分别测 https://api.github.com/ 与 https://registry.npmjs.org/ ，
   只要 HTTP 状态码与耗时（curl -sS -o /dev/null -w '%{http_code} %{time_total}s\n' <url>）。
   另外测一次 git 传输通道：git ls-remote https://github.com/smartlotus/lotussblog.git ，
   公开可读性不管，我要的是这条命令能否建立连接。
5. 持久性：这个环境在两次对话之间会不会被重建？你的工作目录在下次会话还在不在？
   有没有你官方支持的"长期存放文件"的位置？如果有，说清名字与限制（大小、期限）。
6. 凭据规则：我打算只给你一把 GitHub fine-grained PAT，范围是单个仓库、只有 Contents 读写。
   你的官方文档说密钥要"只在当前任务使用、不复述不保存"。请逐字告诉我：
   a) 你有没有官方的安全配置入口可以长期注入这个 PAT（不是让我贴在聊天里）？入口名字是什么？
   b) 如果不允许长期保存，那么每次新会话我都要重新提供一次，对吗？
   c) 你会不会把密钥写进文件、日志、URL 参数或提交记录？请说明你的规则原文。

最后不要给建议，只给：每条的实测输出、测不出来的条目、以及你缺的能力名字。
```

## 判定规则（我按它的回答决定架构）

| 观测结果 | 结论 | 我要做的事 |
|---|---|---|
| 有 node ≥20 + git + 对 api.github.com 与 github git 通道都通 + 有可长期注入密钥的官方入口 | **模式 B 成立，改用它**：Muse 直接在云电脑里跑 `scripts/lotus.mjs … --commit --push`，Worker 降级为可选护栏 | 把 Pages 从直传改成 Git 自动构建（这样一把 PAT 就够，不再需要 Cloudflare 凭据），并把 `muse/` 的说明改成 CLI 手册 |
| 能出网、能跑 git，但密钥只能贴在聊天里 | **模式 B 可用但不好**：每次会话重新给一次凭据，且密钥进入对话上下文（会被保留在会话记录里）。建议只在一次性任务用 | 保留模式 A 为主，模式 B 作为"我自己临时想省事"的备用路径，并在 SECURITY.md 标注这条风险 |
| 没有 node 或没有 git 或不能出网 | **模式 B 不成立**，维持模式 A | 什么都不用改，只补 Muse 侧的连接器接入 |
| 环境每次会话都重建、没有长期存放位置 | 模式 B 每次都要重克隆（能接受），但"项目发给他"这个说法要改成"每次让它重新克隆仓库" | 在 RUNBOOK 里把克隆步骤与耗时写清，并给 `--depth 1` 的轻量克隆 |

## 为什么"把项目发给他"这句话需要改口径

- 项目本体就在 GitHub 上，**不需要"发"**——他克隆即可；聊天里传代码反而会产生一份与仓库无关的副本。
- 真正要"发"的只有两样：**仓库地址**和**凭据注入方式**。
- 一旦他在 VM 里直接改产物 HTML，就会出现"仓库里的产物与他部署出去的版本不一致"的漂移，
  所以模式 B 必须立一条硬规矩：**只许调 `scripts/lotus.mjs`，不许手改 `site/`**，
  `site/` 永远由构建器生成（这条已经写进 CONTRACT，模式 B 同样适用）。
