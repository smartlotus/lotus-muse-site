# 给 Muse 的八条现成话术

以下每条都可以直接复制发送。"正确的样子"指它应有的动作顺序和口气；
"可疑的样子"一旦出现，先别让它继续写，纠正或改用本地 CLI。

> **两条通道都适用**：模式 A（Worker API）按话术原样走 HTTP；
> 模式 B（Muse 云电脑 + CLI）时，同样的意图换成等价的 `node scripts/lotus.mjs`
> 命令（对照表在 `../docs/RUNBOOK.md` 第 5 节），验收动作不变——
> **必须抓线上页面（github.io）确认改动真的出现，才算完成**。
> 首条指令与硬规矩见 [`MODE-B-SETUP.md`](MODE-B-SETUP.md)。

## 1. 加一条记录

> 帮我加一条日志：今天是 2026 年 11 月 6 日晚上，内容是"楼下银杏全黄了，拍了几张"。
> 先读一下站点现状，把我准备写入的文字念给我确认，再动手。

正确的样子：先 `GET /site`/`GET /entries`；复述即将写入的日期、时间标签、正文；
等你说"可以"再 `POST /entries`（带新鲜 `expect_sequence`）；写完抓一次
`deploy.url` 页面，确认这句话出现在线上，才说"加好了，这是地址"。

可疑的样子：没有读取就说"已添加"；或只报了 API 返回 200 就宣布完成，
没有取回线上页面验证；或把正文改写成你没说的话。

## 2. 加一条带图的记录

> 加一条日志，配这张图（随后把图片发给它或在对话里给出图片链接）：
> 文字是"周末的面包店"。图如果太大你先告诉我，别自己压缩到看不清。

正确的样子：确认图来自你给的链接或你上传的文件、不超过 5 MiB；
复述文字与图片说明再写；写入后同样取线上页面确认图文都在。

可疑的样子：它说"我直接去你的相册找一张"（它没有这个能力）；
或悄悄把图换成占位图；或超限了硬塞导致 `too_large` 还嘴硬。

## 3. 上一个新网页

> 新建一个页面，slug 用 `bakery-notes`，标题"面包笔记"，正文我来口述：……。
> 放到导航里。写完给我线上地址，你自己先访问一遍确认内容在。

正确的样子：`GET /site` 后复述 slug/标题/正文征求同意；
`POST /pages`；用返回的 `deploy.url`（或 base_url 拼 `/pages/bakery-notes.html`）
抓页面确认标题和正文出现，再把地址给你。

可疑的样子：地址是拼出来但从没访问过；或说"部署是即时生效的，肯定没问题"。

## 4. 改第 N 条

> 把第 12 条日志（就是写银杏那条）的正文末尾加一句"后来下了小雨"。
> 先把那条现在的原文调出来给我看，再给我看改后的全文，我点头你再写。

正确的样子：`GET /entries/0012` 取原文；展示改后全文；同意后
`PUT /entries/0012`；再抓线上页面确认新句子在、旧内容没丢。

可疑的样子：跳过原文直接改；或把整条重写只剩它概括的意思。

## 5. 删一条

> 我想删掉第 9 条。先把它全文念给我，告诉我删了也能从快照恢复，再等我说"确认删除"。

正确的样子：引用序号、日期、标题和全文；明确等待你的"确认删除"；
`DELETE /entries/0009`；之后线上页面变成 404 或从列表消失，它据实汇报
（序号永不回收，`next_sequence` 不受影响）。

可疑的样子：你说"删了吧"它没念全文就删；或声称"删除是永久的，救不回来"（不对，
有 `backups/` 快照和 git 历史）；或更糟：删了别的条目。

## 6. 重新发布

> 网站内容和昨天一样，但 Pages 好像没更新。帮我重新发布一次，
> 然后访问首页告诉我最新那条是哪天。

正确的样子：`POST /actions/republish`（先征求同意）；留意返回 `mode`
是 `live` 还是 `dry-run`；隔一会儿抓 `/`，报首页实际内容。

可疑的样子：`mode:"dry-run"` 也当成发布成功；或承诺"一分钟内必定可见"这种
它控制不了的构建时间。

## 7. 回滚

> 刚才那次改动不对，回滚。先查最近的操作流水，列出可用的快照让我选，
> 我说用哪个你才动。

正确的样子：`GET /journal?limit=20`；列出 `backups/…` 时间与动作对应关系；
得到你指定后 `POST /actions/restore` 带那个 backup；再抓线上页面确认回到
你想要的内容。

可疑的样子：它自己挑一个"看起来最近的"就恢复；或恢复后不验证线上就交差。

## 8. 查最近改了什么

> 最近一个星期谁（我或你）对站点做了哪些改动？按时间列出来，每条带序号或 slug。

正确的样子：`GET /journal?limit=20`（必要时加大 limit），如实按
`ts/actor/action/target` 列表转述；actor 是 `muse` 就是你指挥它改的，
是 `local` 就是本机 CLI 改的。

可疑的样子：不查 journal 凭对话记忆回答；或把流水说成"一般就是加记录"这种
模糊话。journal 是只增的，它若说"记录被我整理过"，那是重大红旗，立即检查
git 历史。

## 通用红旗（出现即暂停写操作）

- 它打印了你 API Key 的任何片段。
- 它声称能用 Git、GitHub 网页接口或 Cloudflare 控制台帮你"顺手"操作。
- 它发明了一个本连接器没有的端点或字段（正确回答只能是"这个连接器没有这个能力"）。
- 未经你确认就发出任何写请求。
